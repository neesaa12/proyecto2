# ADR-0002 · Proveedor IA del centro y protección de credenciales

## Contexto

Quiero añadir dos acciones que usen el modelo del centro: resumir un apunte `.txt` y clasificarlo por tema. Al mismo tiempo, las tres acciones actuales deben seguir funcionando sin conexión y sin credenciales. El centro es un servicio del aula: ha facilitado una URL, que se guardará solo en `.env`, pero ni esa URL ni el identificador del modelo ni el protocolo están documentados en este repositorio.

## Decisión

- El cliente HTTP es **HTTPX 0.28**, añadido con `uv add "httpx>=0.28,<0.29"`.
- El proveedor vive en `src/tareas/ia.py`, separado de la validación de configuración y del motor de ejecución.
- La CLI ofrece `tareas comprobar-ia` para revisar la configuración local sin mostrar secretos.
- Los valores de `operacion` en `acciones.json` son `mostrar_resumen` y `mostrar_tema`. Sus campos obligatorios son `id`, `operacion` y `patron`; `origen` es opcional y, si se omite, la búsqueda parte de la carpeta `--directorio`. Esto conserva las entradas escritas a mano por el usuario, que no incluyen `origen`.
- No se usa un SDK específico del centro: cuando se conozca su contrato, se implementará un adaptador delante de HTTPX.
- No se inventan la URL, el modelo ni el protocolo. Hasta que el aula los proporcione, las funciones `mostrar_resumen` y `mostrar_tema` explican qué dato falta y no envían nada.

## Lo comprobado sobre HTTPX 0.28

La documentación se consultó con Context7 mediante `resolve-library-id` y `query-docs`:

- `resolve-library-id` devolvió `/websites/python-httpx` y `/encode/httpx`.
- `query-docs` con `/websites/python-httpx` avisó de que no hay documentación indexada específicamente para 0.28 y sirvió la actual.
- `query-docs` con `/encode/httpx` devolvió documentación de la rama `0.28.1`.

La conclusión es que, para un CA local, la forma recomendada es crear un contexto SSL y pasarlo al cliente:

```python
import httpx
import ssl

ctx = ssl.create_default_context(cafile="ruta/al/ca.pem")  # o capath=...
client = httpx.Client(verify=ctx)
```

Pasar la ruta directamente como texto a `verify` está obsoleto en 0.28.1. El código de `httpx._config.create_ssl_context` emite:

```text
`verify=<str>` is deprecated. Use `verify=ssl.create_default_context(cafile=...)`
or `verify=ssl.create_default_context(capath=...)` instead.
```

Por tanto, el proyecto usa `ssl.create_default_context(cafile=...)` para archivos y `capath=...` para directorios, y nunca `verify=False`.

## Protección de credenciales

- `.env.example` contiene solo nombres de variables con valores vacíos. El usuario copia el fichero a `.env` y rellena los valores en su equipo. `.env` ya está ignorado por Git.
- El código **no lee** `.env`. Solo consulta `os.environ`; las variables deben exportarse en la sesión antes de ejecutar la CLI.
- Nunca se imprimen claves ni cabeceras de autorización. Los mensajes de error se limitan a indicar si falta una variable, si el certificado no es usable o si el centro rechazó la autenticación.
- Cuando se implemente la petición real, un `401` o `403` se traducirá a un mensaje genérico; no se mostrará el cuerpo de la respuesta.
- Si se configura `TAREAS_IA_CA`, se usa un contexto SSL con verificación TLS activa. No se desactiva la verificación para resolver problemas de certificado.

## Sin red

Las operaciones `copiar` y `crear_indice` no importan ni llaman al proveedor en tiempo de ejecución: siguen funcionando sin conexión y sin clave. Con `--simular`, las operaciones IA solo enumeran los archivos candidatos; no leen su contenido para envío, no crean el cliente HTTP y no contactan con el centro. Cuando se implemente el envío real y falle la red, se mostrará un mensaje claro con código distinto de cero y sin traceback.

## Consecuencias y pendientes

- **Conexión real pendiente.** Todavía no se ha enviado ninguna petición al centro. Las funciones `mostrar_resumen` y `mostrar_tema` son adaptadores vacíos que avisan del dato que falta; `comprobar-ia` solo valida la configuración local y crea el cliente HTTPX, sin contactar con el centro.
- **Protocolo del proveedor pendiente de confirmar.** Hacen falta el identificador exacto del modelo, el método HTTP, la ruta del endpoint (o confirmación de que la URL facilitada ya es el endpoint completo), el esquema del cuerpo de petición, el campo donde enviar el texto, los campos de respuesta para el resumen y para el tema, y el esquema de autenticación (por ejemplo, si es `Bearer`). Hasta que lleguen, no se inventa ni se envía nada.
- **Consulta con Context7.** La consulta sobre HTTPX 0.28 ya se realizó con `resolve-library-id` y `query-docs` y queda documentada arriba; no está pendiente. No se ha consultado Context7 sobre el contrato del centro porque todavía no existe documentación del proveedor que consultar; cuando se confirme el protocolo, se podrá contrastar allí si procede.
- Las acciones locales (`copiar` y `crear_indice`) y `--simular` no se ven afectadas por estos pendientes: funcionan sin red, sin clave y, en modo simulación, sin modificar archivos.
